# UX-M00 — Binding Design and CI Infrastructure

- **P01**: Immutable HTML SHA-256, token manifest, 50 executable browser cases and semantic rosters; 33 additional extension requirements explicitly pending their reference/fixture adapters. The original prototype remains unchanged. Browser renders are repeated and compared exactly.
- **P02**: Source-bound native instrumentation, real legacy catalog witness and admitted-case capture via tagged production views. Existing native screenshots are retained as witnesses, never relabeled as fidelity. Equivalent fixture, viewport, renderer, density, measured insets, actual role/state and journey evidence are mandatory for every admitted case. Initially no UX-M01–05 routes are admitted; the relevant owning overlay must implement fixture adapters and extensions before admission.
- **P03**: Strict semantic, geometry, typography, color, touch, reviewed region raster limits, and native golden regression checks. Admission is monotonic; missing, extra, stale, unsupported or unapproved data fails closed. No candidate or golden approval is inferred. Final acceptance requires all assigned routes/extensions and approved goldens; external visual and device acceptance remains pending. CI independently recomputes the exact artifacts, bound to source/tree/run/attempt.
- **P04**: Preserve old browser, native, adaptive and CI24 gates, legacy reference bytes, historic roadmap definitions and review workflow. Adopt the seven new UX-M overlays without deleting or downgrading the old ones. Existing functional and security obligations remain independent.

Local source qualification excludes Gradle; Android build, actual instrumentation, hosted design/visual evidence, CI24, native golden review, physical device and release acceptance remain external. The new gates are infrastructure, not a claim that redesigned screens already exist.
